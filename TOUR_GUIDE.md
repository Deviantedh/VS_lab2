# Руководство пользователя и Тур по Системе управления сотрудниками

Руководство по запуску системы и пошаговой проверке ключевых сценариев через Swagger UI или Postman.

---

## 1. Запуск системы

### Поднятие базы данных (для запуска бэкенда из IntelliJ IDEA):
```bash
docker compose up -d postgres
```

### Запуск всего стека в Docker (БД + Бэкенд без IDE):
```bash
docker compose up --build
```

### Запуск тестов:
```bash
./mvnw test
```

### Остановка Docker:
* С сохранением данных БД:
  ```bash
  docker compose down
  ```
* С временной приостановкой:
  ```bash
  docker compose stop
  ```

---

## 3. Пошаговый тур по сценариям (Swagger / Postman)

### Шаг 1. Создание организации (Компании)
* **Зачем:** Создает головное юридическое лицо или сеть заведений.
* **Запрос:** `POST http://localhost:8080/api/companies`
```json
{
  "name": "Сеть городских кофеен"
}
```
* **Ответ:** `201 Created`, получен объект компании с `id: 1`.

---

### Шаг 2. Создание филиала компании
* **Зачем:** Привязывает торговую точку или офис к компании.
* **Запрос:** `POST http://localhost:8080/api/branches`
```json
{
  "companyId": 1,
  "name": "Филиал на Петроградской",
  "address": "Каменноостровский пр., 12",
  "phone": "+78121112233",
  "isActive": true
}
```
* **Ответ:** `201 Created`, получен филиал с `id: 1`.

---

### Шаг 3. Добавление должности в справочник
* **Зачем:** Создает запись в штатном расписании филиала.
* **Запрос:** `POST http://localhost:8080/api/positions`
```json
{
  "branchId": 1,
  "title": "Старший бариста"
}
```
* **Ответ:** `201 Created`, должность с `id: 1`.

---

### Шаг 4. Регистрация нового сотрудника
* **Зачем:** Создает персональную карточку работника в системе.
* **Запрос:** `POST http://localhost:8080/api/employees`
```json
{
  "name": "Иван Смирнов",
  "phone": "+79991234567",
  "birthDate": "2000-05-15",
  "hireDate": "2026-09-01",
  "status": "ACTIVE"
}
```
* **Ответ:** `201 Created`, сотрудник с `id: 1`.
* **Дополнительные операции:**
  * Увольнение сотрудника: `POST http://localhost:8080/api/employees/1/dismiss` (статус `DISMISSED`, фиксируется `dismissalDate`).
  * Прием обратно на работу: `POST http://localhost:8080/api/employees/1/rehire` (статус `ACTIVE`, сброс `dismissalDate`).

---

### Шаг 5. Назначение сотрудника в филиал и на должность (M:N с доп. полями)
* **Зачем:** Фиксирует историю работы сотрудника на конкретной точке с указанием основной ставки.
* **Запрос:** `POST http://localhost:8080/api/employees/assignments`
```json
{
  "employeeId": 1,
  "branchId": 1,
  "positionId": 1,
  "startedAt": "2026-09-01",
  "isPrimary": true
}
```
* **Ответ:** `201 Created`. История назначений доступна по `GET /api/employees/1/assignments`.

---

### Шаг 6. Создание учетной записи пользователя
* **Зачем:** Привязывает системную роль к сотруднику для доступа к API.
* **Запрос:** `POST http://localhost:8080/api/users`
```json
{
  "login": "ivan_smirnov",
  "roleId": 3,
  "employeeId": 1
}
```
* **Ответ:** `201 Created` (роли: 0 - ADMIN, 1 - HR, 2 - MANAGER, 3 - EMPLOYEE; справочник ролей: `GET /api/users/roles`).

---

### Шаг 7. Создание графика смен филиала на календарный период
* **Зачем:** Задает временной диапазон для формирования смен.
* **Запрос:** `POST http://localhost:8080/api/schedules`
```json
{
  "branchId": 1,
  "dateFrom": "2026-09-25",
  "dateTo": "2026-10-01",
  "createdById": 1
}
```
* **Ответ:** `201 Created`, график с `id: 1`.

---

### Шаг 8. Создание плановой смены в графике
* **Зачем:** Задает плановые часы смены и длительность обеденного перерыва.
* **Запрос:** `POST http://localhost:8080/api/shifts`
```json
{
  "scheduleId": 1,
  "date": "2026-09-26",
  "timeFrom": "09:00:00",
  "timeTo": "18:00:00",
  "breakMinutes": 60
}
```
* **Ответ:** `201 Created`, смена с `id: 1`.

---

### Шаг 9. Проверка пагинации и метаданных в HTTP-заголовках (Требование ТЗ)
* **Зачем:** Проверка отдачи метаданных в заголовках `X-Total-Count` и `X-Total-Pages` при чистом теле JSON.
* **Запрос:** `GET http://localhost:8080/api/shifts?page=0&size=20`
* **Ответ:** В Response Headers присутствуют `X-Total-Count: 1` и `X-Total-Pages: 1`.

---

### Шаг 10. Транзакционный сценарий №1: Назначение сотрудника на смену
* **Зачем:** Атомарно проверяет отсутствие пересечений и отпусков, назначает сотрудника и пишет запись в аудит-лог.
* **Запрос:** `POST http://localhost:8080/api/shifts/1/employees`
```json
{
  "employeeId": 1
}
```
* **Ответ:** `200 OK`. Запись в аудит-логе доступна по `GET /api/shifts/1/logs`. Повторный запрос вернет `409 Conflict`.

---

### Шаг 11. Отметка явок (Check-in/out) и Бесконечная лента Slice (Требование ТЗ)
* **Зачем:** Фиксация прихода/ухода сотрудника с автоматическим расчетом опозданий и проверка постраничности без `count(*)`.
* **Приход на смену (Check-In):**  
  `POST http://localhost:8080/api/attendance/check-in`
```json
{
  "employeeId": 1,
  "shiftId": 1,
  "comment": "Прибыл на смену"
}
```
* **Проверка ленты (Slice):**  
  `GET http://localhost:8080/api/attendance?page=0&size=20` — возвращает JSON с флагом `hasNext`.
* **Завершение смены (Check-Out):**  
  `POST http://localhost:8080/api/attendance/1/check-out`
```json
{
  "breakMinutes": 45,
  "comment": "Смена завершена без происшествий"
}
```
* **Ответ:** Автоматически рассчитаны `lateMinutes` и `overtimeMinutes`.

---

### Шаг 12. Транзакционный сценарий №2: Обработка заявки на отпуск
* **Зачем:** При согласовании заявки атомарно создается запись в календаре отсутствий и сотрудник автоматически снимается со всех назначенных смен в этот период.
1. Подача заявки сотрудником:  
   `POST http://localhost:8080/api/requests`
```json
{
  "employeeId": 1,
  "type": "VACATION",
  "requestData": "{\"dateFrom\": \"2026-09-28\", \"dateTo\": \"2026-10-05\"}"
}
```
2. Утверждение заявки руководителем:  
   `POST http://localhost:8080/api/requests/1/process`
```json
{
  "status": "APPROVED",
  "processedById": 1,
  "resolutionComment": "Ежегодный отпуск согласован"
}
```
* **Результат:** Заявка в статусе `APPROVED`, в `GET /api/absences` появилась запись, а со смен в этот период сотрудник автоматически снят с записью в аудит-лог.
